Box가 Hermes Agent용 공식 스킬에 넣은 운영 습관 다섯을, Box를 안 써도 그대로 쓸 수 있는 질문으로 바꿨습니다. 원문이 「한 번짜리 연동에서 빠뜨리기 쉬운 것들」이라 부른 것들이에요. 인용은 전부 공식 아티클 원문 그대로고, 질문으로 바꾼 것은 저희 정리입니다.

1지금 이 도구는 누구 계정으로 붙어 있나요?

「연결됨」만 보고 넘어가기 쉬운 자리입니다. 어느 계정인지 화면에 나오는지, 나오지 않으면 물어서 답하게 할 수 있는지 확인하세요.

원문 — It verifies the current Box user before acting
🔴 아니오면 — 내 권한이 아니라 남의 권한으로 문서를 열고 있을 수 있습니다. 공용 계정·서비스 계정으로 붙어 있으면 원래 못 보던 것까지 보입니다.

2파일을 이름으로 찾나요, 고유 번호로 찾나요?

「어디쯤 있겠지」로 경로를 짜맞추는 도구가 많습니다. 같은 이름의 파일이 둘일 때 무엇을 집는지 시켜 보세요.

원문 — prefers Box item IDs over reconstructed paths
🔴 아니오면 — 폴더가 옮겨지거나 이름이 겹치는 순간 엉뚱한 파일을 집습니다. 그리고 그걸 맞다고 보고합니다.

3한 번에 얼마나 많이 읽어 오나요?

필요한 것만 가져오는지, 폴더째 훑는지 봅니다. 출력이 길수록 맥락에 들어가는 회사 내용도 늘어납니다.

원문 — keeps command output narrow
🔴 아니오면 — 물어본 것 하나 때문에 관계없는 문서 수십 건이 같이 딸려 들어갑니다.

4지우기·권한 변경 앞에서 멈추나요?

「해도 될까요?」를 실제로 묻게 하는 설정이 있는지 확인하세요. 없으면 그건 「알아서 한다」가 아니라 「말없이 한다」입니다.

원문 — asks before permission changes or destructive operations
🔴 아니오면 — 되돌리기 어려운 일이 확인 없이 지나갑니다. 공유 범위가 넓어지는 것도 여기 들어갑니다.

5쓴 다음 되읽어 확인하나요?

「저장했습니다」를 그대로 믿고 있지는 않은지 봅니다. 같은 계정으로 다시 읽어 결과를 확인하는지가 갈림길입니다.

원문 — reads each write back with the same user to confirm the result
🔴 아니오면 — 실패했는데 성공으로 보고되는 경로가 열립니다. 그 위에 다음 작업이 얹힙니다.

🔴 공식이 스스로 적어 둔 한계

우리가 보탠 경고가 아닙니다. 아티클 본문에 그대로 있는 세 문장입니다.

셋째 줄이 특히 중요합니다 — 권한 안이라고 내용까지 안전한 건 아닙니다. 접근은 계정 권한 안이지만, 만들어진 답과 노트에는 그 내용이 그대로 옮겨 담깁니다.

스킬이 뭔지 한 줄로

설정값이 아니라 지시서입니다. 「이런 일은 이렇게 한다」를 가르치고, 통째로 올라가지 않고 필요할 때만 그 부분을 읽습니다.
