Claude Code 피드백 초안 한 장

쓰는 건 Claude 고 보내는 건 사람입니다. 그 사이에 무엇이 있는지 — 언제 써지고, 어디에 쌓이고, 보낼 때 무엇이 같이 가고, 어떻게 끄는지를 한 장에 놓았습니다.

⚡ Claude Code 2.1.247 에 SendFeedback 이 들어갔습니다. 초안은 ~/.claude/feedback/drafts/ 에 쌓이고, /feedback 에서 보고 고쳐 승인해야 나갑니다.

1언제 초안이 써지나

공식 발표 문구 그대로입니다.
① 실패했을 때
세션에서 뭔가 잘못됐을 때 (when something fails)
② 스스로 알아차렸을 때
Claude 가 자기가 틀렸다고 판단했을 때 (when Claude notices it made a mistake)
③ 사용자가 말했을 때
「이거 잘못됐다」고 지적했을 때 (when you tell it something went wrong)
초안 종류
bug · idea · missing_capability — 「버그」만이 아닙니다

2보내면 무엇이 같이 가나

이 킷에서 가장 실무적인 절입니다.
🔴 리포트만 가지 않습니다 — 설명문 + 현재 세션 트랜스크립트 + 정리된 오류 로그가 함께 전송됩니다. 사내 코드나 비공개 자료를 다루던 세션이면 보내기 전에 확인하세요.
공식 설명이 말해 줍니다
/bug 의 명령 설명이 「Report a bug or share your conversation」입니다 — 「대화를 공유한다」가 이름에 들어 있습니다.
대화상자 제목
Submit feedback / bug report
모으는 것
공식 README 「Data collection」 절 — 사용 데이터(코드 수락·거절), 연관된 대화 데이터, /bug 으로 보낸 피드백
반대쪽도 적혀 있습니다
같은 절의 「Privacy safeguards」 — 민감 정보 보관 기간 제한 · 세션 데이터 접근 제한 · 그리고 모아 둔 피드백을 모델 학습에 쓰지 않는다는 방침(「clear policies against using feedback for model training」).

3어디에 쌓이고 어떻게 보나

로컬 설치본 2.1.247 에서 읽은 값입니다.
쌓이는 곳
~/.claude/feedback/drafts/ — UUID 이름의 파일
보관 상한
10건
보는 명령
/feedback(Send feedback to Anthropic or report a bug) · /bug · 별칭 /share
끄는 법
feedbackDrafts 설정 — 릴리스 노트에 「turn off with the feedbackDrafts setting」으로 적혀 있습니다.

4저희가 하지 않은 것

못 잡는 것을 잡는 척하지 않습니다.
초안 생성
일부러 안 했습니다. 시연용으로 하나 만들면 그게 실제 대기열에 쌓이고, 잘못 승인되면 진짜로 전송됩니다.
전송
같은 이유로 안 했습니다.
