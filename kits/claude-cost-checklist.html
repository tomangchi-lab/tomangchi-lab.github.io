1손잡이는 셋입니다

아티클이 첫 문단에서 세 가지로 못박습니다.

“many applications using Claude Platform can cut cost without giving up performance with three fixes: maximize the prompt cache hit rate, remove anti-patterns from your prompts when upgrading to frontier Claude models, and calibrate effort to the task”
  • 캐시 — 앞부분이 그대로면 다시 계산하지 않습니다. 값이 가장 크게 움직이는 자리입니다.
  • 지시문 — 옛 모델의 약점을 메우려 넣은 주문이 지금은 값이 됩니다.
  • effort — 일의 무게에 맞춥니다. 높다고 늘 좋지 않습니다.
셋은 서로 곱해집니다. 캐시를 고친 다음 지시문을 걷어내고, 그 위에서 effort 를 재는 순서가 아티클의 순서입니다.

2캐시 점검 8항

아래는 아티클의 팁을 «내 프롬프트에서 눈으로 볼 수 있는 것»으로 옮긴 항목입니다. 하나씩 짚어 보세요.

  • 시스템 프롬프트에 지금 시각·요청 ID 같은 매번 바뀌는 값이 들어 있지 않은가 — 앞부분이 바이트 단위로 같아야 읽습니다
  • 도구 정의가 매 요청마다 순서가 바뀌지 않는가 — 도구는 프롬프트 맨 위에 붙습니다
  • 안 변하는 것(도구 정의·시스템 프롬프트)이 앞, 늘어나는 대화가 뒤인가
  • 대화 도중에 effort 를 바꾸고 있지 않은가 — 이 값도 앞부분에 실려 캐시를 깹니다
  • 거의 안 쓰는 도구를 defer_loading 으로 미뤄 뒀는가
  • 대화가 길어질 때 캐시 끊는 자리를 뒤로 옮기고 있는가
  • 도구 호출이나 서브에이전트가 5분을 넘겨 부모 캐시가 만료되지 않는가 — 그러면 1시간짜리를 씁니다
  • 세션이 열릴 때 미리 데워 두는가 — max_tokens: 0 으로 한 번 보냅니다
모델·effort를 바꿔야 한다면 어차피 캐시가 깨지는 순간(대화 압축 같은 때)에 같이 바꾸세요.

3지시문 안티패턴 6종

이름내 프롬프트에서 이런 꼴왜 값이 되나
검증 의식“두 번 확인해”, “답하기 전에 검증해”곧이곧대로 지켜서 같은 조회를 두 번 합니다
강조 부스터“최대한 꼼꼼히”, “CRITICAL: YOU MUST ALWAYS…”말이 길어지고 도구를 더 부릅니다
절차 강제“스크래치패드에 단계별로 생각해”모델이 이미 하는 일 위에 한 겹 더 쌓입니다
낡은 예시옛 모델 실수를 고치려 넣은 few-shot긴 추론을 흉내 내게 가르칩니다
어긋난 규칙“정책 안이면 환불” + “승인 없이 환불 금지”최신 모델은 둘 다 지키려다 멈춥니다
낡은 설정손으로 잡아 둔 thinking budget 같은 것새 모델에서는 요청이 거부되기도 합니다
여섯 개를 하나씩 심어 재 봤더니 — “Running /claude-api prompt-audit removed the anti-patterns, decreasing costs by 14.6% and increasing accuracy by 5.3% on average”
정확도가 «오른» 이유가 재밌습니다. 어긋난 환불 규칙 때문에 줘야 할 환불 네 건을 붙들고 있었고, 손으로 만든 스크래치패드가 모델의 내장 사고와 부딪혀 도구 호출을 생각 안에 적고 실행하지 않은 티켓이 세 건이었습니다.

4effort 고르는 법

effort 는 «얼마나 열심히 할지»입니다. 낮으면 빨리 결론에 닿고, 높으면 따져 보고 대안을 찾습니다.

Claude Fable 5 · 어려운 코딩 50문제한 문제 값점수
low$5.3511.5%
max$19.0030.9%

점수는 약 2.7배(+19점) 오르는데 값은 약 3.5배입니다 — “raises the score about 2.7x (+19 points) for about 3.5x the cost”

  • 높다고 좋은 게 아닙니다. 필요보다 오래 재면 값과 시간만 늘고 답이 나빠질 수 있습니다. 「Deliberation only helps while there's still evidence to find.」
  • 낮다고 싼 것도 아닙니다. 증거가 모자란 채로 멈춥니다 — 「The answer looks finished, but it's built on partial information.」
  • 더 센 모델을 낮은 effort 로 쓰는 쪽이 약한 모델을 세게 굴리는 것보다 쌀 수 있습니다.
  • 마지막 한 칸이 측정 오차 안이면 그건 돈만 더 내는 것입니다.

5명령 세 개가 하는 일

명령언제무엇을
prompt-audit최신 모델로 막 옮겼을 때작업 폴더의 프롬프트·스킬·도구 설명을 훑어 안티패턴을 걷어냅니다
cost-optimize값이 어디로 새는지 모를 때토큰이 어디로 가는지 프로파일하고 캐시·배치·출력 길이로 줄입니다
hillclimb평가셋이 있을 때학습/시험으로 갈라 설정을 바꿔 가며 값과 성능을 같이 찾습니다

hillclimb 을 고객문의 벤치에 돌린 결과 — 처음 못 본 티켓 14건에서 90.5% (원래 설정 78.6%) 를 약 5분의 1 값에 냈습니다.

7이 킷이 하지 않은 것

  • 이 문서의 수치는 전부 앤트로픽이 아티클에 실은 값입니다. 벤치마크를 다시 돌린 것이 아닙니다.
  • prompt-audit·cost-optimize·hillclimb 를 토망치랩 코드에 돌려 본 결과는 여기 없습니다. 돌리면 Claude API 에 과금이 붙고 프롬프트 파일이 바뀝니다.
  • 같은 절감률이 당신 애플리케이션에서도 나오는지는 이 문서가 답하지 못합니다. 위 점검 8항은 눈으로 볼 수 있는 것이고, 절감폭은 재 봐야 압니다.
