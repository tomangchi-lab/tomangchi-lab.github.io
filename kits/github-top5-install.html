1i-have-adhd — 답부터 말하게

ayghri/i-have-adhd · 이번 주 +15,924 · 누적 43,649 · MIT

무엇을 해주나. 코딩 도우미가 답을 뒤에 묻어 두지 못하게 하는 스킬입니다. 진단이나 설정이 아니라 출력 규칙만 바꿉니다.

어떻게 돌아가나. 규칙 10개를 늘 켜 둔 지침으로 얹습니다 — 다음 할 일을 먼저, 여러 단계는 번호로, 목록은 5개까지, 끝인사·되풀이·군더더기는 금지. 그래서 「좋은 질문이에요」로 시작하던 문단이 명령 한 줄 + 번호 단계로 바뀝니다.

쓰면 좋은 사람. 답이 길어서 결론만 찾느라 매번 스크롤하는 사람.

설치 방법

  1. 쓰는 도구의 채팅창을 엽니다 (명령어가 아니라 프롬프트입니다).
  2. 아래 한 줄을 그대로 붙여 넣고 보냅니다.
  3. 도구가 리포의 지침 파일을 읽고 스스로 깔아 줍니다.
Install the i-have-adhd skill/plugin from https://github.com/ayghri/i-have-adhd, refer to the repo's AGENTS.md for instructions.
💡 설치 확인: 다음 질문의 답이 다음 할 일 한 줄로 시작하면 걸린 겁니다. 규칙 원문은 리포의 SKILL.md 에 있습니다.

규칙을 내 취향대로 고치고 싶으면 리포를 포크해 SKILL.md 를 고친 뒤, 원본을 지우고 내 사본을 얹습니다. 포크와 원본이 이름이 같아서 먼저 지우지 않으면 부딪힙니다.

claude plugin uninstall i-have-adhd
claude plugin marketplace remove i-have-adhd
claude plugin marketplace add <your-username>/i-have-adhd
claude plugin install i-have-adhd@i-have-adhd
⚠️ 막히는 자리: 위 네 줄을 쓴 뒤에는 클로드 코드를 껐다 켜야 새 사본이 잡힙니다.

2ponytail — 코드를 덜 쓰게

DietrichGebert/ponytail · 이번 주 +9,272 · 누적 136,817 · MIT

무엇을 해주나. 「오래 다닌 선배 개발자」의 판단을 에이전트 안에 넣습니다. 날짜 입력 하나에 라이브러리를 깔고 래퍼를 쓰고 스타일시트를 더하던 버릇을 멈춰 세웁니다.

어떻게 돌아가나. 코드를 쓰기 전에 사다리를 타고, 걸리는 첫 칸에서 멈춥니다 — ① 이게 꼭 있어야 하나 ② 이 코드베이스에 이미 있나 ③ 표준 라이브러리가 하나 ④ 플랫폼 기본 기능이 하나 ⑤ 이미 깐 의존성이 하나 ⑥ 한 줄로 되나 ⑦ 그제야 최소한의 코드. 사다리는 문제를 이해한 다음에 타는 것이라고 리포가 못 박아 뒀습니다.

쓰면 좋은 사람. 시키지 않은 파일이 자꾸 늘어나서 리뷰가 길어지는 사람.

설치 방법 — 클로드 코드

  1. 아래 첫 줄을 보냅니다.
  2. 답이 돌아오면 두 번째 줄을 따로 보냅니다. 한 번에 붙이면 설치가 안 됩니다.
  3. 새 대화를 엽니다.
/plugin marketplace add DietrichGebert/ponytail
/plugin install ponytail@ponytail

설치 방법 — 코덱스

codex plugin marketplace add DietrichGebert/ponytail
codex plugin add ponytail@ponytail

코덱스는 설치 뒤 codex 를 실행해 /hooks 를 열고, 두 개의 생명주기 훅을 확인해 신뢰로 표시한 다음 새 스레드를 시작합니다.

⚠️ 막히는 자리: 플러그인이 작은 Node.js 훅 두 개를 돌리기 때문에 node 가 PATH 에 있어야 합니다. 없으면 오류가 안 나고 조용히 상시 활성화만 꺼집니다 — 스킬 자체는 돌아가서 눈치채기 어렵습니다. nvm·Nix 를 쓰면 비대화형 셸의 PATH에도 들어 있어야 합니다.
💡 설치 확인: 「날짜 입력 하나 만들어 줘」 같은 걸 시켜 보고, 컴포넌트 대신 한 줄이 돌아오면 걸린 겁니다.

3archify — 말하면 구조도

tt-a1i/archify · 이번 주 +10,442 · 누적 60,004 · MIT

무엇을 해주나. 코드베이스나 말로 한 설명을 눌러 볼 수 있는 시스템 지도로 바꿉니다. 채팅 안에서 끝나고, 결과는 파일 한 장입니다.

어떻게 돌아가나. 에이전트가 형식이 정해진 JSON 을 쓰고, archify 가 그걸 정해진 규칙대로 HTML·SVG 로 굳힙니다. 그림을 에이전트가 직접 그리는 게 아니라서, 같은 입력이면 같은 그림이 나옵니다. 구조·워크플로·시퀀스·데이터 흐름·상태도 다섯 종류를 그리고, 결과물은 혼자 도는 HTML 이라 링크만 넘겨도 열립니다.

쓰면 좋은 사람. 구조를 남에게 보여줄 일이 잦은 사람 — 리뷰·온보딩·발표.

설치 방법

  1. 터미널에 아래 줄을 넣습니다. 안내를 따라가는 설치입니다.
  2. 쓰는 도구를 껐다 켭니다.
  3. 채팅에 그려 달라고 말합니다 — 리포를 열지 않아도 됩니다.
npx skills add tt-a1i/archify -g

커서에서 물어보는 화면 없이 깔려면 이 줄을 씁니다.

npx -y skills add tt-a1i/archify --skill archify --agent cursor --global --copy --yes

깔지 않고 한 번만 써 보려면 이 줄을 씁니다.

npx skills use tt-a1i/archify@archify --agent codex

첫 그림은 이렇게 시켜 보세요. 리포 없이 설명만으로 됩니다.

Use Archify to draw: Browser -> API -> Redis cache -> PostgreSQL fallback.

코드에서 뽑으려면 리포를 열어 두고 이렇게 시킵니다.

Analyze this repository, then use archify to create a high-level runtime architecture diagram.
💡 안내 설치는 cursor, codex, claude-code, opencode 를 알아봅니다. 그 다음은 「Redis 추가해」·「인증을 왼쪽으로」 처럼 채팅으로 고쳐 갑니다.

4ECC — 한 판으로 까는 쪽

affaan-m/ECC · 이번 주 +8,086 · 누적 257,271 · MIT

무엇을 해주나. 앞의 셋이 스킬 하나라면 이건 묶음입니다. 에이전트에게 도구가 아니라 일하는 절차를 통째로 깔아 줍니다.

어떻게 돌아가나. 짓기 전에 계획하고, 테스트로 확인하고, 새 창에서 제 작업을 다시 보고, 남길 것을 기억하고, 반복되는 것을 스킬로 만드는 한 바퀴를 심습니다.

plan -> test -> implement -> review -> verify -> remember -> improve

리포의 말로는 이 과정을 프롬프트마다 다시 짓는 대신 한 번 깔아서 에이전트가 일하는 방식으로 만드는 것입니다.

쓰면 좋은 사람. 프롬프트마다 같은 절차를 다시 적고 있던 사람, 도구를 여러 개 오가는 사람.

설치 방법

  1. Node.js 18 이상인지 확인합니다.
  2. 아래 한 줄을 터미널에 넣고 안내를 따라 고릅니다 — 설치·업데이트·범위 변경이 같은 줄입니다.
  3. 쓰는 도구를 껐다 켭니다.
npx ecc-universal@2.2.1 setup

npm 이 버전·캐시 오류를 내면 등록된 버전부터 확인합니다.

npm view ecc-universal version
⚠️ 막히는 자리: 플러그인 설치 쪽은 Git 과 Claude Code 2.1 이상이 PATH 에 있어야 합니다. 그리고 리포도 안내 설치와 수동 설치를 겹쳐 쌓지 말라고 적어 뒀습니다 — 둘을 겹치면 어느 쪽이 도는지 알 수 없게 됩니다.
💡 버전을 고정한 것은 보안 검사가 아닙니다. 리포도 그렇게 적어 뒀어요 — 남의 코드를 돌리는 일이니 회사 저장소보다 개인 프로젝트에서 먼저 보세요.

5순서 체크리스트

  • 지금 불편한 것 하나를 0번 표에서 고른다
  • 그 리포의 설치 한 줄을 그대로 붙여 넣는다 (ponytail 은 두 줄 따로)
  • 도구를 껐다 켠다
  • 같은 질문을 하나 다시 던져 답이 달라졌는지 본다 — 안 달라졌으면 설치가 안 된 것
  • 며칠 써 본 뒤에 다음 걸 더한다
💡 넷 다 MIT 이고, 전부 파일을 읽고 쓰는 도구에 얹힙니다. 회사 저장소에 깔기 전에는 개인 프로젝트에서 먼저 돌려 보세요.

6다섯 번째는 설치할 스킬이 아니다

fmtlib/fmt · 누적 25,751 · 2012년 12월 시작 · MIT

{fmt} 은 C 의 stdio 와 C++ 의 iostreams 를 대신하는 출력 포매팅 라이브러리입니다. C++ 표준의 format 과 print 가 여기서 나왔고, 형식 문자열이 틀리면 컴파일할 때 걸립니다.

에이전트와는 아무 상관이 없습니다. 이 목록에서 유일하게 AI 도구가 아닙니다 — 그래서 이 킷에 설치 줄이 없습니다.
