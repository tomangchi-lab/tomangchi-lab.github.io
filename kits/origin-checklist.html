무료 플랜은 불가 — 공식 문서

1옮기기 전 확인 5가지

  • 요금 — 유료 플랜(Pro·Teams·Enterprise)에 포함되고, 별도 Origin 요금은 문서에 없습니다. 무료 플랜은 안 됩니다.
  • 개방 단계 — «Access opens in stages». 플랜이 맞아도 순서대로 열립니다.
  • 팀 vs 개인 — 팀은 레거시 프라이버시 모드면 Origin을 못 켭니다. Privacy Mode로 먼저 전환해야 합니다. 엔터프라이즈는 관리자가 대시보드에서 언제든 끌 수 있습니다.
  • 기존 GitHub 연동 — 옮기는 게 아니라 미러입니다. GitHub 레포를 복사해 계속 따라가고, 푸시는 GitHub로 흘러가며 원본도 GitHub입니다.
  • 이름 — 코드베이스 이름(네임스페이스)은 베타 동안 한 번 정하면 못 바꿉니다.

2GitHub 동기화 시작 — 공식 절차

준비물 3가지(문서 «Prerequisites»)

  • Pro·Teams·Enterprise 플랜의 Cursor 계정 + Origin 접근
  • 레포를 가진 조직/계정에 Cursor GitHub 앱 연결
  • 동기화할 레포의 GitHub admin 권한

켜기 — cursor.com/codebase → Get Started → 코드베이스 이름 정하기 → (관리자) 레포 생성·접근 권한 설정

동기화 4단계

  1. cursor.com/codebase 열기
  2. Sync from GitHub 선택
  3. GitHub 조직과 레포 고르기
  4. 동기화 확인

💡 이슈와 CI는 GitHub에 남습니다 — 문서 원문: “Issues and CI configuration stay on GitHub unless you rebuild them elsewhere.”

🔎 아직 확인 안 된 것 — 공식 문서 미기재

  • 이슈 이관 — GitHub Issues를 Origin으로 옮기는 방법: 문서에 없음(«이슈는 GitHub에 남는다»까지만)
  • CI 이관 — GitHub Actions 워크플로 이관: 문서에 없음. 네이티브 파이프라인은 Buildkite, PR 프리뷰는 Vercel, 빌드는 Depot 앱으로 붙입니다(공식 연동 3종)
  • Origin 전용 요금·용량 한도 — 문서에 없음(플랜 포함만 명시)
  • GitHub 없이 Origin만 쓰는 구성 — 레포 신규 생성은 가능하지만, «GitHub가 원본»인 미러 구조 밖에서의 운영 가이드는 문서에 없음
  • 에이전트 네이티브 기능 — changelog «Agent-native features ship soon» 예고만, 내용 미기재

공식 문서에 생기면 이 페이지를 갱신합니다. 저희도 아직 Origin에 실제 레포를 올려 보지는 않았습니다.
